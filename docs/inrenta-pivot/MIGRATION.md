# Как переделать текущий проект

Принцип: **каркас оставляем, ядро пишем заново рядом, старое прячем флагом — не удаляем.**
Переписывать с нуля нет смысла (потеряем авторизацию, деплой, SEO-маршруты), переделывать объявления в предложения — дорого и запутанно.

## Оставить как есть

- Next.js 15, Drizzle, PostgreSQL, деплой, домен inrenta.ru, окружение.
- Авторизация (Auth.js) — понадобится для подтверждения карточки и кабинета проката.
- Маршрутизация по городам и категориям, уже спроектированная SEO-архитектура URL.
- Общий layout: шапка, подвал — перекрасить по `DESIGN_SYSTEM.md`.

## Спрятать флагом (`FEATURE_P2P=false`), не удалять

- Создание объявлений пользователями, «Разместить объявление».
- Календарь занятости и бронирование по датам.
- Поток «заявка → подтверждение владельцем в течение суток → телефон».
- Чаты.

Позже, когда подтверждённые прокаты захотят принимать брони, эти части вернутся уже для них.
Старые баги (смешанные ULID/UUID в `users.id`, гонка в `setBlockedDates`, недостающие FK) чинить только там, где новые таблицы касаются `users`.

## Убрать сразу

- Все формулировки «аренда у людей рядом», «берите у соседей», «частники» — главная, title, meta description, тексты.
- Тестовые объявления из выдачи и пустые категории (оставить инструмент и электровелосипеды).

## Написать заново

Порядок совпадает с 12-недельным планом (решение 21 декабря 2026).

### Шаг 1. Данные (неделя 1–2)
- [ ] Миграция из `code/schema.aggregator.ts` (сверить формат id).
- [ ] Сид `item_class`: 10 классов инструмента (перфоратор SDS-plus/SDS-max, отбойный молоток до/свыше 20 Дж, бетономешалка до/свыше 160 л, виброплита до/свыше 100 кг, штроборез, генератор до 3 / 3–7 кВт, вышка-тура, УШМ 125/230, моющий пылесос, пароочиститель) + модели электровелосипедов.
- [ ] Скрипт импорта CSV (`data/offers.template.csv`) → `rental_shop` + `offer`.
- **Готово, когда:** в базе ≥5 предложений в ≥8 из 10 классов.

### Шаг 2. Расчёт (неделя 2)
- [ ] `lib/pricing.ts` из `code/pricing.ts` + тесты `code/pricing.test.ts` (8 тестов проходят).

### Шаг 3. Страница сравнения (недели 2–4)
- [ ] Маршрут вида `/[city]/[classSlug]` (например `/krasnodar/prokat-perforatora`), серверный рендер для SEO.
- [ ] Компоненты по `DESIGN_SYSTEM.md`: `SearchBar` (компактный), `ResultTabs`, `OfferTicket`, `FiltersSidebar`, `SavingsHint`, `RecheckBlock`, `PickupOnlyBlock`.
- [ ] Параметры (даты, доставка, район, вкладка, фильтры) — в query-строке, чтобы ссылка открывала ту же выдачу.
- [ ] Свой текст на странице: выбор класса, FAQ. Без чужих фото и текстов.
- [ ] Мобильная версия: параметры одной строкой, первое предложение на первом экране.
- **Готово, когда:** 10 страниц инструмента + 3–5 страниц электровелосипедов в индексе Яндекса к неделе 5.

### Шаг 4. Учёт обращений (неделя 1–3, до теста через Директ)
- [ ] Серверный эндпоинт записи `lead_event` + цели Яндекс Метрики: `show_phone`, `request`, `regular_request`, `price_outdated`, `claim_click`.
- [ ] Номер телефона отдаётся только по клику (иначе клики не посчитать).
- **Готово, когда:** тестовый клик виден и в Метрике, и в `lead_event`.

### Шаг 5. Главная (неделя 3–4)
- [ ] Большой `SearchBar` «что · когда · куда», карточки категорий с ценой «от», три пункта «почему цене можно верить».

### Шаг 6. Прокаты (недели 8–12)
- [ ] Страница проката (карточка «составил inrenta» / «подтверждена»), кнопка «Это ваш прокат?».
- [ ] Подтверждение: вход через существующую авторизацию → привязка `owner_user_id` после проверки звонком.
- [ ] Кабинет: правка своих цен (обновляет `verified_at`, `verified_by = shop`), отчёт обращений за месяц, место в сравнении.
- [ ] Подменные номера (коллтрекинг) для подтверждённых — позже, когда появится оплата за звонок.

## Проверка перед тестом через Директ

- [ ] Устаревшая цена никогда не получает плашку «Самый дешёвый».
- [ ] Прокат без доставки при включённой доставке не в рейтинге, а в блоке «Только самовывоз».
- [ ] Итог совпадает с расчётом из `pricing.ts` на тех же данных.
- [ ] Страница быстрая на телефоне, текст контрастный, кнопки ≥44px.
