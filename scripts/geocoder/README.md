# Свой геокодер: импорт адресов (OSM + ГАР) → Postgres

Адресный индекс агломерации Краснодара для поля «Где» (подсказки и координаты), обратного геокодирования
(«Моё местоположение») и геокодирования адресов прокатов при CSV-импорте. Внешних сервисов в рантайме нет.
Область: bbox агломерации 38.60..39.45 × 44.85..45.30 плюс районы ГАР-корней целиком (Северский, Динской,
Тахтамукайский, Теучежский, городские округа Краснодар и Адыгейск); вырезка OSM для этого — шире,
38.40..39.70 × 44.60..45.45.

- Контракт данных и поиска: `src/lib/geocoder/types.ts` (`GeoIndexData`). Импорт добавил в него только
  необязательную `IndexStreet.line` (линия улицы) и уточнил смысл `precision` и `parentId` (см. «Изменения»).
- Поиск (опечатки, раскладка, сокращения) делает `src/lib/geocoder/`. Здесь только данные.
- Таблицы описаны в `drizzle/schema.ts` (блок «Свой геокодер»), миграции `drizzle/migrations/0007_*.sql`
  и `0008_*.sql` (`geo_streets.line`): `geo_places`, `geo_streets`, `geo_houses`, `geo_pois` и журнал
  `geo_imports` с версией данных.
- Сервер читает таблицы через `src/server/geocoder-index.ts` → `getGeoIndexData(citySlug)`. Данные кэшируются
  в памяти процесса, версию из `geo_imports` сервер сверяет раз в минуту и при смене перечитывает таблицы.
  Пока новые данные грузятся, отдаются прежние. Запасной путь — JSON-файл из `GEOCODER_INDEX_FILE`: он берётся,
  если в БД нет импорта для города.

## Атрибуция

  адресные точки, границы пунктов, СНТ, объекты. Таблицы `geo_*` — производная база OSM (ГАР и OSM сведены

  «Лицензия (ODbL)».
- **ГАР ФНС России** (https://fias.nalog.ru/, открытые данные https://www.nalog.gov.ru/opendata/7707329152-fias/):
  официальные названия пунктов и улиц, дома и земельные участки, почтовые индексы. Условия: ссылка на источник,
  не искажать смысл. Коммерческое использование разрешено.
- На сайте рядом с OSM нужна строка «Адреса: ГАР ФНС России (fias.nalog.ru), открытые данные». Её добавит
  команда интеграции (подвал и `/kak-schitaem-ceny`).

## Запуск

```bash
bash scripts/geocoder/prepare.sh      # docker + curl; DATABASE_URL — из окружения или .env
pnpm db:export-geo                    # БД → data/geocoder/build/index.krasnodar.json (тесты, замер, запас)
```

- OSM — своя вырезка `data/geocoder/raw/osm/agglomeration.osm.pbf`: `prepare.sh` качает выгрузку Geofabrik по
  Южному ФО (315 МБ, ~1 мин) и режет её `osmium extract -s smart` по `GEOCODER_BBOX` (по умолчанию
  38.40,44.60,39.70,45.45; ~10 с). Карта OSRM (`data/osrm/src`) уже: на её краю терялись Северская,
  Пластуновская, Крепостная, Убинская. Готовая вырезка переиспользуется, перекачать — `GEOCODER_REFRESH_OSM=1`,
  своя — `GEOCODER_PBF=<файл>`. В индекс из широкой вырезки попадает только область выше: пункты вне bbox
  агломерации, не найденные в ГАР (соседние районы), отрезаются вместе с улицами и домами (`trim_to_area`).
- ГАР, регионы 23 и 01: `gar_remote_zip.py` читает оглавление полного `gar_xml.zip` (58 ГБ) по HTTP Range
  и берёт только `AS_ADDR_OBJ`, `AS_ADM_HIERARCHY`, `AS_HOUSES`, `AS_HOUSES_PARAMS`, `AS_STEADS`.
  Это ≈1 ГБ сжатых, ≈6 мин. Файлы **не распаковываются**: сжатые данные архива пишутся как есть в
  `<имя>.XML.deflate`, `gar_extract.py` распаковывает их на лету (+≈20 с к разбору). Распакованные XML — ≈8 ГБ
  (один `AS_HOUSES_PARAMS` региона 23 — 4,1 ГБ), на VPS с диском 15 ГБ это забило бы диск вместе с Postgres.
  Старые распакованные `.XML` (прежние запуски) читаются так же; их можно удалить — следующий запуск
  перекачает ГАР сжатым. Ссылку на свежую выгрузку даёт `GetLastDownloadFileInfo`. Если выгрузка уже лежит
  в `data/geocoder/raw/gar`, её берём как есть. Перекачать заново: `GEOCODER_REFRESH_GAR=1`.
- Диск: `data/geocoder/raw` ≈ 1,1 ГБ (ГАР сжатым + вырезка OSM 30 МБ; на время скачивания выгрузки OSM — ещё
  315 МБ), `data/geocoder/work` ≈ 130 МБ (промежуточные CSV и `osm.pkl`, отчёт `report.md`).
- Python запускается в одноразовых контейнерах из образа `inrenta-geocoder-py`: python:3.12-slim, libexpat,
  pyosmium, shapely, numpy, psycopg, rapidfuzz. Образ `prepare.sh` собирает сам, дальше он берётся из кэша
  docker. В Linux контейнер работает в сети хоста (БД на 127.0.0.1:5432), в macOS обращается
  к `host.docker.internal`. Для dev без docker: `GEOCODER_PYTHON=<venv>/bin/python`, работает и на Python 3.9.
- Сколько занимает (dev, M-серия): ГАР — 2 мин, OSM — 20 с, сборка — 30 с, запись в БД — 15 с (COPY,
  одна транзакция). Пик памяти ≈4 ГБ, из них 3 ГБ на иерархию ГАР.
- Запись в БД: `DELETE` строк города + `COPY` + новая строка `geo_imports`, всё в одной транзакции. Если любой
  шаг падает, в БД остаются прежние данные.
- Обновлять раз в месяц вместе с картой OSRM (ГАР у ФНС обновляется каждую неделю).
- Проверки без данных: `python textnorm.py --selftest`, `python build.py --selftest`. `prepare.sh` запускает
  их первыми. TS-часть: `tests/geocoder/import-index.test.ts`.

| Файл | Что делает |
|---|---|
| `prepare.sh` | обёртка: вырезка OSM → ГАР по Range → разбор ГАР → разбор OSM → сборка и запись |
| `gar_remote_zip.py` | оглавление и выборочная распаковка ZIP по HTTP Range (из разведки) |
| `gar_extract.py` | ГАР → `work/gar/gar_objects.csv` (НП, СНТ, улицы с GUID) и `gar_houses.csv` (дома + участки, индекс) |
| `osm_extract.py` | PBF → `work/osm.pkl`: адреса (узлы, контуры, мультиполигоны), здания без адреса, улицы, места, СНТ, ЖК, объекты |
| `textnorm.py` | нормализация: тип и ключ улицы, каноническая подпись, номер дома, СНТ, пункты, ЖК |
| `build.py` | сборка, сопоставление, интерполяция, отчёт, запись в БД |
| `export.ts` | БД → JSON `GeoIndexData` (та же функция загрузки, что у сервера) |

## Как собирается

1. **Места** (`geo_places`, `kind`):
   - **пункты** (`city`/`town`/`village`/`hamlet`) — полигоны OSM `place=*`. Если внутри полигона есть узел
     с тем же именем, центр берётся по узлу. Пункты без полигона — по узлу;
   - **округа** — имена и синонимы из `geo-data.ts`, контуры OSM (admin_level 9);
   - **микрорайоны** — `geo-data.ts` (центр, синонимы «ЮМР», «ФМР»…) плюс OSM suburb/quarter/neighbourhood.
     Совпадающие по имени объединяются, контур берётся из OSM. В OSM микрорайон часто и узлом, и контуром
     («Калинино», «Крепость», «Северный», два «Пашковских»): одноимённые ближе 1,5 км или внутри контура друг
     друга — одно место. Родитель микрорайона в Краснодаре — округ;
   - **родитель пунктов в черте города**: посёлки, хутора, станицы и СНТ внутри городского округа
     (граница OSM admin_level 6 «городской округ Краснодар» или корень ГАР «г. Краснодар») → `parentId` =
     Краснодар (Лазурный, Российский, Старокорсунская, Елизаветинская… — 52 места);
   - **СНТ** — OSM `place`/`landuse=allotments` и neighbourhood с именем «СНТ …». Одно имя в пределах 3 км —
     одна запись с именем «СНТ Имя». Синонимы собираются из подписей домов (`addr:city`/`addr:suburb` вида
     «Родник СТ», «Кубаноска снт») и из ГАР («тер. СНТ …»). Если у СНТ нет контура, он строится по его домам.
     Если СНТ есть только в подписях, создаётся новое место. Безымянный контур получает имя по подписям домов
     внутри;
   - **СНТ и микрорайоны ГАР** без пары в OSM становятся местами. Центр — медиана их улиц, найденных в OSM.
     Таких улиц нет: СНТ небольшого пункта (село, хутор, контур до ~3×3 км) — точка пункта, дома честно
     `place` («≈»; СНТ «Адыгея» Пчегатлукая); в крупном пункте место не берётся;
   - синонимы пунктов: типы из ГАР («ст-ца Елизаветинская», «станица …», «пгт …»), `alt_name`/`old_name`,
     опечатки из `addr:city` (от 5 домов и похожие на имя, например «Елизаветенская»);
   - ЖК («ЖК …», «Жилой комплекс …») — это объекты (`geo_pois`), а не микрорайоны.
2. **Привязка к пункту — только по положению**, `addr:city` не используется. Точка относится к самому
   маленькому полигону пункта, в который попала. Вне полигонов — к ближайшему узлу пункта (до 2,5 км) или
   к ближайшему полигону (до 1 км). «Зона» СНТ определяется так же.
3. **Улицы** (`geo_streets`) собираются из кусков `highway` с именем и из домов с `addr:street`, в том числе
   там, где линии улицы нет. Группа — (пункт, ключ имени). Внутри группы элементы связываются, если между ними
   меньше 150 м, или меньше 400 м в одной зоне (одно СНТ либо вне СНТ). Каждая компонента — отдельная улица.
   Поэтому одноимённые улицы разных пунктов и разных СНТ остаются разными записями, а длинная улица
   не режется.
   - **Тип улицы участвует в склейке** (`textnorm.effective_type`): «улица Каляева» и «проезд Каляева»,
     «улица Кубанская» и «улица Кубанская Набережная» — разные улицы, даже если линии рядом. Тип внутри имени
     важнее родового «улица»: «ул. Ростовское Шоссе» — шоссе. Кусок без типа («Каляева» в `addr:street`)
     присоединяется к ближайшей типизированной улице; дома с типом, которого у линий группы нет вовсе
     («улица Чекистов» у линии «проспект Чекистов»), — к улице с линией (ошибка тега).
   - Улица, дома которой лежат в разных СНТ и повторяют номера («Энтузиастов, 62» в СНТ «Связист» и «КТТУ»
     за 250 м), делится по СНТ.
   - Улица с двумя нумерациями (номера повторяются дальше 200 м) делится, только если это подтверждает ГАР:
     в пункте ≥2 одноимённые улицы ГАР и номера отделяемой части ≥50 % — у другой из них и заметно лучше
     (+20 % номеров), чем у улицы ГАР основной части (`split_by_numbering`). Без подтверждения повторы — ошибки
     OSM или корпуса одного адреса («Калинина, 13/…» — кампус КубГАУ, 15 номеров повторяются за 0,2–1 км),
     копию выбирает шаг 4. На данных 30.09 ни одна улица не прошла подтверждение: пробный вариант без ГАР
     разрезал «улицу 1-го Мая» (4 повтора на 900 номеров) и кампус на Калинина — оба неверно.
   - Место улицы (`placeId`) — СНТ, если там больше половины её домов, иначе пункт.
   - Ключ имени (`name_key`): без типа, «им./имени», инициалов, пунктуации; ё→е, «1-й»→«1», «40-летия»→«40 лет»,
     римские «XXI/ХХ1»→21, «Ново-Садовая»=«Новосадовая», порядок слов неважен.
   - Подпись «как на табличке»: берётся самое частое написание линий, «им.» убирается, инициалы остаются
     («улица Кобцевой Н.С.»), ё сохраняется. В синонимах сначала полные имена (официальное имя ГАР — первым),
     затем короткие («улица Кобцевой»), затем написания как есть; до 16. «улица» ставится впереди («улица Красная»), остальные типы с прилагательным — после
     («Рождественская набережная», «1-й Лиговский проезд», «Ростовское шоссе»). Остальные написания
     (OSM, `addr:street`, ГАР, `alt_name`) идут в синонимы.
   - Точка улицы — середина самой длинной связной части линии. Если линии нет — дом, ближайший к медиане
     домов.
   - Линии без типа и без домов («Подъезд к ж. д. ст. …», трассы) не берём.
   - **Линия улицы** (`geo_streets.line`, `IndexStreet.line`) — куски OSM, склеенные и упрощённые до ~3 м,
     `[[lon, lat], …]`: для обратного геокодирования («ближайшая улица», когда дома рядом нет). 8 тыс. улиц,
     40 тыс. точек (≈1 МБ).
4. **Дома OSM**: контуры зданий, включая мультиполигоны, адресные узлы, `addr2:*`, «57; 59» — это два адреса.
   - Точка контура — центроид, а если он вне контура — point-on-surface.
   - Адресный узел внутри здания без адреса, или если такое здание одно в пределах 15 м, переносится в точку
     здания.
   - `addr:place` без улицы даёт адрес по месту (`streetId=null`). Если `addr:place` — это «улица …», адрес
     считается уличным.
   - Дубли (улица + номер) склеиваются: здание важнее точки, большее здание важнее меньшего. Если копии дальше
     300 м друг от друга (в OSM два объекта с одним адресом), остаётся копия на своём месте в нумерации: точка
     номера по соседям улицы (правила интерполяции ГАР, без этой целой части и без других номеров с копиями);
     копия берётся, если она ближе 150 м к оценке, а остальные дальше вдвое + 100 м (`predicted_copy`, 481 из
     671 случая). Оценки нет — копия среди соседних номеров («14/5» рядом с «14/4», «14/6», «14/5Б»), затем —
     где больше объектов.
   - Точка дома `osm` и `osm+gar` — всегда точка его объекта OSM; ГАР её не двигает (проверка в отчёте).
5. **ГАР**:
   - пункт ГАР → наш пункт: по имени без типа, при одноимённых — по числу общих улиц; имя, единственное и в ГАР,
     и в OSM, берётся и без общих улиц (хутор Воликов — узел без контура). Пункта с таким именем в OSM нет — пункт
     OSM, не занятый ГАР, по улицам: общих ключей ≥3, ≥50 % улиц ГАР и ≥30 % улиц пункта OSM («п. отделения № 2
     СКЗНИИСиВ» = «Водники», 1 032 дома; «с. Шабановское» к Горячему Ключу по «Школьной» и «Лесной» не
     приклеивается);
   - улица ГАР → наша улица (правила, без ручного словаря):
     0) тип: при нескольких кандидатах — того же типа; улица OSM другого типа не берётся, если такой тип есть
        у одноимённой улицы ГАР того же пункта («проезд Каляева» не станет «ул. Каляева»);
     1) точный ключ. Одноимённые улицы ГАР одного пункта («ул. Калинина» центра, «Пашковского жилого массива» и
        «ТЭЦ»; «ул. Весёлая» ДНТ «Садовод» и ДСНТ «Труд»; 13 «Центральных» в СНТ Елизаветинской) делят
        одноимённые улицы OSM один к одному: сначала улица OSM в том же СНТ (нумерации СНТ «1…N» номерами
        не различить), затем больше общих номеров, затем рядом с контуром СНТ. Улица ГАР без пары не садится на
        занятую улицу, на улицу в чужом СНТ и на улицу с домами без единого общего номера — становится улицей
        только из ГАР в своём СНТ (`place`). Раньше все садились на самую большую улицу OSM, и дома вставали
        на чужую нумерацию («Вишнёвая» СНТ «Радист» — в СНТ «Охрана» за 2 км);
     2) имя с именем, инициалами, званиями и без них («ул. им. Дмитрия Благоева» = «улица Благоева»,
        «К.Маркса» = «Карла Маркса», «им. Героя Советского Союза Иванова» = «улица Генерала Иванова» —
        `textnorm.TITLE_WORDS`);
     3) окончание фамилии: «ул. им. Шпак» = «улица Шпака», «ул. Чуц» = «улица Чуца» (при общих номерах);
     4) нечёткое совпадение ≥90 при общих номерах домов; числа в именах обязаны совпасть (раньше
        «пр-д 3-й Темрюкский» садился на «2-й Темрюкский проезд», «36-я Линия» — на «35-ю», «10-й Сахалинский» —
        на «1-й»); одна буква разницы — только разночтение: гласная ↔ гласная, удвоенная согласная, ь/ъ
        («ул. им. Фелицына Е.Д.» = «улица Фелицина», «пр-д Деповской» = «Деповский проезд», «Алычовая» =
        «Алычёвая»; «Калиновая» ≠ «Малиновая», «Кроткий» ≠ «Короткий») — 23 улицы;
     5) та же улица в соседнем пункте (≤5 км от контура), если совпадает много номеров: граница пунктов в ГАР
        и OSM расходится («ул. им. Виктора Скоробогатого» г. Краснодар лежит в Елизаветинской) — 381 улица.
        Не берётся улица, которую своя одноимённая улица ГАР её пункта объясняет не хуже («ул. Веселая»
        х. Октябрьский не садится на «улицу Весёлую» п. Южный по 11 общим мелким номерам).
     Одноимённые улицы различаются по СНТ из ГАР и по пересечению номеров;
   - дом ГАР, который есть в OSM, помечается `osm+gar` (+ GUID, индекс);
   - дома, которых нет в OSM, получают точку по соседям (`NumberLine`, затем `LineModel`). У каждого номера
     своя точка: номер переводится в позицию на улице (`fine_pos`), и «1», «1/1», «1/10», «1а» встают в разные
     места отрезка до следующего соседа. Позиция строго внутри [n, n+1) и без совпадений: вид хвоста (буква,
     дробь, корпус «к», строение «с», литера) — своя полоса, значение — внутри полосы, второй хвост — в 10 раз
     мельче («36ак11», «401в/1»). Хвосты одной целой части на улице (ГАР + OSM) разводятся по порядку с шагом
     min(0,12; 0,9/(n+1)) (`spread_positions`). Прежняя формула читала «к» в «52к1» как букву и упиралась
     в потолок 0,6: «50/15» … «50/84», «89и» и «89к», «52к1» … «52к4» стояли в одной точке. Целая часть
     с ≥8 хвостами без своего дома в OSM («Кирпичная, 8/1 … 8/73» — 230 адресов комплекса) — `street` («≈»):
     точки на отрезке — сантиметры друг от друга, «до дома» их не поставить (879 домов).
     `precision=interpolated` — только способы, что по проверке «исключи один» укладываются в критерий плана
     (медиана ≤10 м, 90 % ≤40 м):
     1) между соседями той же чётности (разрыв ≤20 номеров, соседи ближе 150 м): медиана 6,5 м, 90 % — 24 м;
     2) только в СНТ, где участки нумеруют подряд: любая чётность, разрыв ≤4: 9,6 м / 43 м.
     Остальное — честное «≈», `precision=street`, но с лучшей точкой, что есть (не точкой улицы):
     3) та же целая часть номера («21к2» у «21к1»; вдоль отрезка к соседу): медиана 20 м, 90 % — 118 м;
     4) за краем известных номеров, не дальше 4 номеров и 60 м: 14 м / 78 м;
     5) вдоль линии улицы по дальним соседям той же стороны (разрыв ≤60 номеров, ≤800 м по линии, за краем
        ≤10 номеров): медиана 24 м, 90 % — 91 м (точка улицы для тех же домов — 244 м / 940 м).
     Точка «примагничивается» к зданию без адреса, если оно одно в радиусе 20 м и не занято другим номером
     (в том числе адресным узлом OSM, севшим на это здание: раньше «Морозная, 14» вставала в точку
     «Батумская, 4/2»).
     Способа нет — точка улицы (`street`);
   - улица только в ГАР: точка — центр СНТ, небольшого пункта или компактного квартала ГАР («мкр.», «кв-л»,
     контур до ~3×3 км), дома получают `precision=place`. В крупных пунктах без квартала такие улицы
     не берём, потому что честной точки для них нет;
   - земельные участки ГАР входят как дома, если номер не совпадает с домом. Гаражи (`г-ж`) не берём.
6. **Объекты** (`geo_pois`): ТЦ, рынки, ЖК, вузы и колледжи, больницы, вокзалы и автостанции, аэропорт,
   стадионы, парки. У «ТЦ X» синоним «X», у «ЖК X» — тоже «X». Адрес берётся из тегов, иначе у здания с адресом
   в пределах 40 м. Одинаковые имена ближе 500 м склеиваются.

`id` — стабильные ключи источника (хеш OSM-объекта, GUID ГАР, улица + номер), а не ULID. Повторный импорт
тех же выгрузок даёт те же `id`. У дома в JSON `id` нет (так в контракте), в таблице он есть.
