# Подход B — «поле скоростей»

Время поездки OSRM (профиль `profile/`) плюс постоянная приложения должны совпадать с 2ГИС
(будний день 13:00) на новых адресах. Вместо трёх колец (центр ≤3 км / город ≤8 км / окраины)
используется **поле множителей времени на сетке 2 × 2 км** по агломерации (bbox 38.75–39.30 ×
44.93–45.22, 23 × 18 узлов), отдельно для магистралей (fast, primary, secondary) и для
остальных улиц (tertiary, minor, service).

Train (в выборке): 11.3%. Перекрёстная проверка по группам точек train: 13.5%.

### Что дало выигрыш

1. **Привязка точки к проездам (`snap_to_service = true`)**, CV 16.9 → 15.2%, короткие
   поездки 21.9 → 17.9%, км медиана 5.7 → 4.5%. Рабочий профиль запрещал привязку к
   service/living_street, и дом в глубине квартала привязывался к дальней улице (часто с
   другой стороны или к односторонней) — маршрут выходил в 2–5 раз длиннее или короче.
2. **Выбор маршрута отделён от времени.** Вес участка OSRM = длина / «скорость выбора
   маршрута» класса (`route_speeds` → `rate_factors` в params.lua), вес поворота — из
   `route_turn`; время (duration) — из скоростей класса и поля. Проезды (service) для выбора
   маршрута почти запрещены (3 км/ч: с них только выезжают), secondary предпочтительнее
   primary (47 против 30). Поле в выбор маршрута **не входит** (проверено: с полем в весе CV
   хуже на 0.6 п. п., км 5.3% против 4.4%). Подбор — по точности времени (CV) + 0,2 × км.
3. **Поле вместо колец** — главный выигрыш по времени: на тех же маршрутах (CV по train)
   класс × кольца 17.4% → поле 13.2%; на val 19.5% → 15.4%.

Кольца почти ничего не дают поверх скоростей классов; поле выигрывает везде, сильнее всего —
мосты через Кубань (21.7 → 11%), окраины и поездки 7–15 км. Короткие поездки выигрывают меньше
всего: там ошибка в основном от несовпадения маршрута (у 2ГИС другой подъезд к дому).
Два поля (магистрали / прочие) лучше одного на 0.4–0.9 п. п.; три группы, шаг 1.5 или 3–4 км — не лучше.
Поле: на юге (Адыгея, трассы) q ≈ 0.3–0.5 (трасса быстрее городской скорости класса),
на севере-западе (45.09–45.11, 38.93–38.98: Ростовское шоссе / Западный обход) q до 3.

(`data/calibration/approaches/B-field/compare_models.json`, скрипт `compare_models.py rw1`; маршруты `seg_B-field-*.json` сохранены в `data/calibration/approaches/B-field/seg/` — для перезапуска положить в `data/calibration/`.)

## Как устроено в профиле (`profile/car.lua`)

- `field_speed` (после `WayHandlers.surface`): скорость пути делится на средний по длине пути
  q; q в точке — билинейно по узлам `P.field.q` (магистрали) или `P.field.q2` (прочие,
  `P.field.group`). Координаты узлов пути берутся из `way:get_nodes()` → `node:location()`
  (работает в OSRM 5.27 при `--location-dependent-data`). `way:get_location_tag('zone')` не
  подходит: OSRM определяет зону пути по одному (последнему) узлу, длинный путь целиком попал
  бы в одну ячейку. Проверено: разница «поле по участкам маршрута» и «поле по путям» — 0.3%.
- `route_preference` (после `WayHandlers.penalties`): вес = скорость × `rate_factors[класс]`,
  поле убирается из веса (`× q`), если не `field_in_route`.
- `process_turn`: `turn.duration` — из `turn/signal/u_turn/intersection_penalty`, `turn.weight`
  — из `route_turn` (+ `turn_weight_extra`).
- `snap_rule`: `snap_to_service` = true | "main" | false, `snap_to_fast`.
- `zones.geojson` — прежние кольца, нужны только если в params.lua заданы `zone_speeds`
  (в итоговом профиле их нет). `field_cells.geojson` — поле для просмотра (q_main, q_local по ячейкам).

## Формула приложения

```
км     = distance_m / 1000                  // OSRM /table, без поправки (медиана OSRM/2ГИС = 1.00)
минуты = (f · duration_s + β) / 60,  f = 1, β = 48.75 с   // app_formula.json
```

Всё зональное — внутри графа; приложению нужны только `f` и `β`. f подбиралась по
внепапочным (CV) прогнозам: оптимум f = 0.99–1.00, β ≈ 36–42 при f=1 — то же, что даёт подбор.

## Воспроизвести

```bash
cd data/calibration
PY=python3   # numpy, scipy
A=../../scripts/osrm/calibration/approaches/B-field
# 1) (сделано) выбор маршрута: route_search2.py start → start_params.json
#    snap_to_service=true, route_speeds {fast 48, primary 30, secondary 47.4, tertiary 35.1, minor 22, service 3}
# 2) поле: 2 итерации «граф → маршруты → подбор» (порт 5012, контейнер osrm-B — в bf.py)
$PY $A/loop_b.py $A/start_params.json X 2 --step 2 --groups 0,0,0,1,1,1 --lamg 0.3 --lams 0.1 --lamr 0.03
#    → approaches/B-field/params_X2.{json,lua}; params_X2.lua = profile/params.lua
# 3) граф и прогноз как на сайте
cd ../.. && PROFILE_DIR=$A/profile bash scripts/osrm/build.sh data/osrm/builds/B-field-final $A/profile/params.lua
bash scripts/osrm/calibration/serve.sh data/osrm/builds/B-field-final 5012 osrm-B
cd data/calibration && $PY ../../scripts/osrm/calibration/predict_table.py http://127.0.0.1:5012 approaches/B-field/best_pred.json 1 48.75
$PY ../../scripts/osrm/calibration/score_val.py approaches/B-field/best_pred.json --part val
```

Подбор (`fit.py`): время маршрута T = Σ_участок b·c[класс]·q(x) + α·штрафы + γ·перекрёстки + β,
где b — время участка без поля; минимизируется средняя |отн. ошибка| с равным весом диапазонов
длины (IRLS ≈ L1, как min_balanced) + λs·Σ(q_a − q_b)² по соседним узлам + λr·Σ(q − 1)² +
λg·Σ(q_маг − q_проч)²; q ∈ [0.3, 3]. λ — 5-кратной проверкой по группам точек train
(пара в проверке, если хоть один конец в группе); λs=0.1 взят вместо 0.03 (CV 13.48 против 13.39 —
в пределах шума, поле глаже). Val использован 6 раз, только для сравнения готовых вариантов.

Файлы: `bf.py` (параметры → params.lua, сборка, признаки), `segfeat.py` (маршруты с геометрией
по участкам ~150 м), `fit.py`, `loop_b.py`, `route_search2.py`, `variants.py`, `compare_models.py`,
`rings_loop.py` (кольца на тех же маршрутах, для сравнения).

## Риски

- Поле местами резкое (соседние узлы 0.3 и 3.0) — там, где мало маршрутов в эталоне; на новом
  адресе в такой ячейке время может заметно ошибаться. Узлы без данных ≈ 1.
- Штрафы поворотов при подборе ушли почти в ноль (turn 3 с, светофор 0.8 с): время
  перекрёстков забрали поле и постоянная на перекрёсток — на маршрутах с необычным числом
  поворотов возможен сдвиг.
- Точка привязывается и к проездам (service): изредка это двор без выезда или парковка — маршрут длиннее.
- Эталон — один срез 2ГИС (13:00 буднего дня); новые развязки и мосты требуют пересборки и пересчёта.
