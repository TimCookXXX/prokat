# Подход C: дороги, по которым OSRM ездит, а навигатор нет

Цель — км и типичное время на машине (будний день 13:00) как у 2ГИС на новых адресах.
Всё подбиралось на train; val — только для сравнения трёх готовых вариантов.

## Что нашлось

1. **Главное расхождение — привязка точки, а не срезки.** Старый профиль не ставил адрес на
   `service`/`living_street` (`snap_to_service=false`): точка во дворе, на парковке ТЦ, в промзоне
   цеплялась к улице за 50–100 м и подъезжала не с той стороны (r:4 — парковка у Уральской:
   OSRM 6 км вместо 0.4 км у 2ГИС, в обратную сторону — на 7.5 км короче). 2ГИС ставит точку на
   ближайший проезд. Привязка ко всем проездам: |log км| на train 0.117 → 0.090, медиана км 5.5% → 4.2%.
2. **Выбор пути отделён от времени.** Калиброванные скорости старого профиля (дворовые 42–50 км/ч
   в центре быстрее магистралей 24–39) заставляли OSRM срезать дворами. Теперь вес выбора пути —
   свои скорости `route_speeds` (близко к стандартному OSRM: 90/55/65/40/25/15) и свои штрафы
   `route_turn`, а время участка — калиброванное. Маршрут от скоростей времени не зависит, поэтому
   подбор времени точный и без пересборок (пробные сборки `probe.py`). Выбор пути по
   калиброванному времени (как «честный» профиль) — хуже по км (0.096 против 0.089).
3. **Шлагбаумы и ворота** (`barrier=gate|lift_gate` без access-тегов) — непроходимы
   (`block_barriers`): CV по группам точек 14.24% → 14.00%. Эффект небольшой и по узлам разный
   (`data/calibration/approaches/C-diverge/blocked_ways.json`).
4. **Блокировки отдельных участков по id не внесены.** Ридж log(км 2ГИС / км OSRM) на индикаторы
   участков с эффектами точек даёт кандидатов, но почти все — подъезды к одной точке. Вмешательство
   (блокировка / вес ×0.5) с 5-кратной CV по группам точек train: без пользы или хуже
   (0.0891 → 0.0891…0.0913). Пример из задачи (Яблоновский, Базовская → Тургеневское) после
   исправления привязки уже не расходится (средний log км ≈ 0).
   Правила тоже проверены и отклонены: штраф грунтовок, безымянных, `service`, `access`-проездов,
   съезда с улицы во двор — км не лучше.
5. **Время**: скорости класс × зона, штрафы перекрёстка/поворота/разворота и поправки 288 улиц
   (улицы с ≥10 маршрутами train; ридж к 1, λ по CV) — `fit_time.py`, `make_t.py`. Длительность
   светофора фиксирована (4.26 с): в OSRM 5.27 она входит в вес и меняет маршруты. Без поправок
   улиц CV 17.5%, с ними 14.0%. β от длины и f≠1 — без выигрыша.

## Воспроизвести

```bash
cd data/calibration
PY=…/venv/bin/python; C=../../scripts/osrm/calibration/approaches/C-diverge
$PY $C/osmindex.py                                   # индекс карты (pyosmium)
$PY $C/opt_route.py a                                # выбор пути по км train (покоординатно)
$PY $C/full.py r1g approaches/C-diverge/params_r1g.json   # сборка, пробы, подбор времени + CV
# итоговый params.lua — в profile/; граф:
cd ../.. && PROFILE_DIR=$C/profile bash scripts/osrm/build.sh data/osrm/builds/C-recipe $C/profile/params.lua
```

Анализ: `analyze.py`, `points_eff.py`, `tags_eff.py`, `way_ridge.py`, `who.py`, `near.py`,
`cv_block.py` (CV блокировок), `cv_time.py` (CV времени). Метрики — `evalkit.py`/`score_val.py`.

## Отличия car.lua от рабочего

- `block_ways` (id участков вне графа), `block_barriers` (типы барьеров-узлов);
- `route_pref`: `route_speeds` (скорости выбора пути класс × зона), `pref` (множители веса:
  грунтовка, безымянные, restricted, вид service), `slow_ways`; время участка не меняется;
- `route_turn`: веса манёвров для выбора пути отдельно от длительностей;
- `snap`: к каким проездам может привязаться адрес (итог: ко всем);
- `highway_turn_classification` для веса съезда во двор (`route_turn.to_minor`, в итоге не используется).

Риски: поправки 288 улиц подобраны по 120 точкам train — на val выигрыш держится (15.4%),
но после изменений дорог их надо пересчитывать. Привязка к дворам даёт иногда подъезд
через закрытые проезды, не помеченные шлагбаумом в OSM.
