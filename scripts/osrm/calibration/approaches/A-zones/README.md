## Что в профиле (`profile/car.lua`, `profile/params.lua`, `profile/zones.geojson`)

- **Темп** (с/м) = темп класса дороги (fast/primary/secondary/tertiary/minor/service) в зоне
  + добавка съезда (`*_link`) + добавка плохого покрытия; × `1/road_factor` для улицы по названию.
  Зоны — 5 колец от центра (45.0355, 38.9753): 2 / 5 / 9 / 15 км, дальше z5 (`zones.geojson`,
  свойство `zone`). Покрытие больше не «срезает» скорость, а добавляет темп.
- **Штрафы поворотов** (`pen`): светофор и левый поворот отдельно «с магистралью» (secondary и
  выше, по `priority_class` сторон перекрёстка) и без; перекрёсток (>2 дорог) — «съезд с местной
  на магистраль» и прочие; правый поворот; разворот.
- **Выбор пути**: вес проездов во дворах (`service`, `living_street`) ×4 (`rate_factors` 0.25) —
  навигаторы не ведут через дворы; время по ним не меняется. Точка не привязывается к
  service/living_street (`no_start`).
- **Поправки улиц** (`road_factors`, 151 улица): улицы, по которым сквозной путь идёт у ≥20 пар
  train; ρ — ридж к 0, λ по перекрёстной проверке; действует на всём протяжении улицы, как в OSRM.
- Пробы (`probe = …` в params.lua) — только для подбора: вес пути тот же, время кодирует признак.

## Формула приложения (`app_formula.json`)

Входы: из OSRM /table — `sec` (duration) и `m` (distance); координаты двух точек.

```
km_osrm = m / 1000
crow    = max(50, расстояние по прямой между точками, м)        // равнопромежуточно, cos широты
km      = 1.02 * km_osrm                                         // показываемые км
t = sec
  + 164.4                                                        // β0, с
  + 23.36 * max(0, 2  - km_osrm)                                 // кусочно-линейная β(км)
  + 35.76 * max(0, 5  - km_osrm)
  - 34.46 * max(0, 10 - km_osrm)
  - 0.400 * sec * max(0, 1 - 2.5 * crow / m)                     // маршрут OSRM > 2.5× прямой — вероятно, лишний круг
минуты = max(t, 30) / 60
```

β(км) по OSRM: 0 км → +45 с, 2 км → −5 с, 5 км → −8 с, ≥10 км → +164 с.
Всё — арифметика, переносится в TypeScript (`src/lib/compare/config.ts` / `routing.ts`) как есть.

## Как воспроизвести

```bash
cd data/calibration
PY=python3   # numpy, scipy
A=../../scripts/osrm/calibration/approaches/A-zones
# итоговый граф и прогноз
(cd ../.. && PROFILE_DIR=$A/profile bash scripts/osrm/build.sh data/osrm/builds/A-zones-final $A/profile/params.lua)
(cd ../.. && bash scripts/osrm/calibration/serve.sh data/osrm/builds/A-zones-final 5011 osrm-A)
$PY $A/predict_app.py http://127.0.0.1:5011 $A/params_final.json approaches/A-zones/best_pred.json
$PY ../../scripts/osrm/calibration/score_val.py approaches/A-zones/best_pred.json --part val
```

Подбор с нуля (итерации «граф → маршруты и пробы → подбор», ~1–3 мин на итерацию):

```bash
$PY $A/pipe.py <версия> <params.json>          # граф + 8 проб → feat_<версия>.json
$PY $A/fit.py  <версия> <params.json> <out.json> --roads 20 --lam 0.003,0.01 --lamr 0.0001,0.0003 --app exc_s:2.5
$PY $A/loop.py W <старт.json> 5 --damp 0.5 --lam 0.003,0.01 --roads 20 --lamr 0.0001,0.0003 --app exc_s:2.5
```

Путь, которым пришли к итогу: p0 (старый профиль в новом car.lua) → loop `a` (классы × 3 кольца)
→ `e1` (дворы ×4 по весу) → `R4` (кольца 2/5/9/15) → `T`/`U` (8 штрафов поворотов, β по 2/5/10 км,
exc_s) → `V` (поправки улиц) → `W` (затухание 0.5) → W6 + km×1.02. Параметры версий —
`data/calibration/approaches/A-zones/params/`.

## Что пробовали и не взяли (по CV на train)

- приоритет крупных улиц над жилыми (rate residential 0.5–0.7), вес поворотов — км лучше, время хуже;
- запрет привязки к половинкам разделённых магистралей, `approaches=curb` — хуже;
- β по числу концов в центре, по микрорайону (−0.2 п.п., не стоит сложности), по длине привязки
  (−0.16 п.п., но это поле /table waypoints, не distance/duration);
- кольца 3/8, 4/10, 1.5/3/5/8/12/18 — в пределах шума, 2/5/9/15 чуть лучше.

## Риски

- Поправки улиц (151) и темпы колец подобраны с малым риджем: на train 14.3%, на CV 16.8%, на
  val 17.6% — часть выигрыша — подгонка; скорости некоторых классов в кольцах неправдоподобны
  (fast в z3 36 км/ч, secondary в z3 51 км/ч) — компенсируют друг друга и поправки улиц.
- Короткие поездки (0–3 км) — 23% на val: основная ошибка — другой путь (км), а не скорость.
- Поправки улиц по названию ухудшают короткие поездки (~+1 п.п. в 0–3 км), улучшая длинные.
