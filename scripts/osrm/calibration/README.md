# Калибровка профиля OSRM по 2ГИС

Профиль `scripts/osrm/profile` (скорости дорог, штрафы, поле скоростей по агломерации в `params.lua`)
подобран так, чтобы время и километры OSRM совпадали с эталонными маршрутами 2ГИС.
Пересчитывать — раз в квартал и после крупных изменений дорог (мост, развязка).

Эталон и промежуточные файлы лежат в `data/calibration/` (в git не попадают: это ответы
2ГИС, их хранение — по условиям ключа). Скрипты запускаются из этой папки:

```bash
cd data/calibration
PY=python3   # нужны numpy и scipy
S=../../scripts/osrm/calibration
```

## 1. Эталон (ключ 2ГИС `DGIS_API_KEY` в `.env`)

```bash
$PY $S/points.py                                   # points.json: центры микрорайонов, пригороды, улицы, прокаты из БД
$PY $S/collect.py day     2026-09-30T10:00:00Z 8 10 2   # 13:00 МСК, 8 блоков по 10×10 пар → gis.jsonl
$PY $S/collect.py morning 2026-09-30T05:30:00Z 3 10 2   # те же пары утром, вечером, ночью —
$PY $S/collect.py evening 2026-09-30T15:00:00Z 3 10 2   # для поправок по часу (TRAFFIC_BY_HOUR)
$PY $S/collect.py night   2026-09-30T19:00:00Z 3 10 2
```

`start_time` — ближайший будний день. Демо-ключ принимает матрицу не больше 10×10,
тарифицируется каждая пара.

## 2. Подбор (первая версия: класс × зона, поправки магистралей)

```bash
bash ../../scripts/osrm/build.sh data/osrm/builds/v1 ../../scripts/osrm/profile/params.lua
bash $S/serve.sh data/osrm/builds/v1                # калибровочный OSRM на 127.0.0.1:5002
$PY $S/features.py v1 http://127.0.0.1:5002         # маршруты с раскладкой по классам и зонам
$PY $S/fit2.py v1                                   # скорости класс × зона, штрафы
# params_2.json из fit2_v1_day.json (см. loop.py), затем итерации — до устойчивости:
$PY $S/loop.py 2 5
$PY $S/fit3.py <версия> --through                   # поправки магистралей (road_factors)
$PY $S/honest_eval.py <версии…>                     # итог на адресах вне подбора
```

Проверка честная: отложенные 20% точек не участвуют в подборе, ошибки считаются на парах,
где хотя бы один конец новый (у пользователя адрес всегда новый).

Итоговая версия (поле скоростей) подобрана по протоколу train / val / контроль
(`split.json`: точки train и val, контрольные пары — `vault/test.jsonl`, открываются один раз,
в конце). Рецепты подходов — `approaches/` (B-field — поле скоростей, D-app — поправка в
приложении, F-final — итог: граф B + формула, README там).

## 3. Выкладка

Итоговые `car.lua` и `params.lua` → `scripts/osrm/profile/`; коэффициенты `f`, `β` (для
итоговой версии — `approaches/F-final/f_formula.json`) и множители по часу → `src/lib/compare/config.ts`
(`OSRM_TIME_FACTOR`, `OSRM_TIME_BASE_S`, `TRAFFIC_BY_HOUR`). Затем `bash scripts/osrm/build.sh
data/osrm` и `docker compose restart osrm`.

## Итог 29.09.2026 — поле скоростей (F-final, будний день 13:00)

Граф подхода B (версия X2: скорости классов, штрафы, выбор маршрута отдельными весами, поле
