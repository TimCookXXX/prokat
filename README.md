# inrenta — маркетплейс аренды вещей

Сервис «арендуй что угодно рядом»: в духе Авито, но для аренды. Инструмент,
спорт, туризм, платья, фототехника — вещь берут на день или на неделю у
человека из своего города.

**Какую проблему решает.** Вещи, которые нужны пару раз в год, покупать
невыгодно, а найти их поблизости негде: объявления об аренде тонут в общих
досках, где нет ни календаря занятости, ни понятных условий залога. inrenta
собирает такие вещи в каталог по городам и категориям и доводит людей до
договорённости.

Любой пользователь одновременно арендатор и продавец: размещает своё и бронирует
чужое, отдельной регистрации «для бизнеса» нет. Платежей внутри сервиса нет —
оплата и залог остаются между людьми.

## Возможности

- **Каталог по городам и категориям** — серверный рендеринг, фильтры, поиск,
  канонические адреса, sitemap и JSON-LD.
- **Объявления** — фотографии, цены за час, сутки и неделю, залог, количество
  единиц; публикуются сразу, без премодерации.
- **Бронь как заявка** — арендатор выбирает даты, владелец подтверждает. Даты
  занимаются только после подтверждения, телефоны раскрываются сторонам тогда
  же. У каждой вещи — календарь занятости.
- **Профиль продавца** — витрина с обложкой, его объявления, «на сайте с» и
  значок «Проверен».
- **Кабинет** — свои объявления, входящие и исходящие заявки, календарь с
  ручным закрытием дат, профиль и настройки.
- **Админка** — модерация объявлений и заявок, справочники городов и категорий,
  верификация и бан пользователей.
- **Три способа входа** — Яндекс ID, VK ID и почта с паролем.

## Стек

- Next.js 16 (App Router, Server Components, Server Actions), React 19, TypeScript
- PostgreSQL 16 + Drizzle ORM
- Auth.js v5, database-сессии
- S3-совместимое хранилище, обработка изображений через `sharp`
- Tailwind + CSS-токены, светлая и тёмная темы
- Vitest
- Деплой: docker-compose (Caddy + app + Postgres + backup), HTTPS от Let's Encrypt

## Быстрый старт

```bash
cp .env.example .env             # как есть годится для локальной разработки
docker compose up -d db          # поднять Postgres
pnpm install
pnpm db:migrate && pnpm db:seed  # схема + тестовые данные
pnpm dev                         # http://localhost:3000
```

Быстрый вход в dev-режиме: `GET /api/dev/login`, для админа —
`/api/dev/login?role=admin`. Тестовые владельцы из сида —
`owner1@seed.local` … `owner5@seed.local` с паролем `inrenta-dev-12345`.

Сидов два, и они независимы: `pnpm db:seed` кладёт демо-данные с вымышленными
товарами, `pnpm db:seed:real` — витрину из настоящих объявлений (таблицы в
`seed_real/`, формат описан там же в `README.md`). Оба поднимаются на чистой
базе поодиночке и в любом порядке; дерево категорий у них общее.

Без `STORAGE_*` загрузка изображений недоступна (`/api/upload` отвечает 503) —
для локальной разработки это нормально. Без `SMTP_*` письма печатаются в
консоль dev-сервера.

## Команды

```bash
pnpm dev                 # dev-сервер
pnpm build               # production-сборка (сначала остановить dev)
pnpm test                # тесты
pnpm exec next typegen   # типы роутов (нужны tsc при typedRoutes)
pnpm exec tsc --noEmit   # проверка типов
pnpm check-theme         # проверка CSS-токенов
pnpm db:generate         # сгенерировать миграцию из drizzle/schema.ts
pnpm db:migrate          # применить миграции
pnpm db:seed             # демо-данные (Казань, вымышленные товары)
pnpm db:seed:real        # реальные данные из seed_real/
pnpm seed:photos         # обработать и залить в бакет фотографии из seed_real/Фото/
pnpm db:studio           # drizzle studio
```

Линтера в проекте нет: конфигурации ESLint не заведено, а команду `next lint`
в Next 16 удалили. Статическую проверку выполняет
`pnpm exec next typegen && pnpm exec tsc --noEmit`.

## Структура

```

src/server/     чтение данных и Server Actions
src/lib/        доменная логика и инфраструктура
src/components/ UI
drizzle/        схема БД и миграции
theme/          токены, шрифты, тексты, SEO-дефолты
tests/          Vitest
docs/           документация
```
